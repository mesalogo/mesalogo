# i18n in the frontend

> Agent workbook for adding, editing or refactoring user-facing strings.
> Read this **before** writing any new page, modal, or message.
>
> Background: until 2026-05, the frontend kept all translations in two
> 3000-line monolithic files (`frontend/src/locales/zh-CN.ts` and `en-US.ts`).
> The two files drifted (e.g. `// =====` section comments became misaligned
> starting from section #42) and ~6200 user-visible CJK strings ended up
> hard-coded inside `.tsx` files, bypassing i18n entirely. We split locales
> into per-feature namespaces and started migrating pages off hard-coded
> strings. See `docs/agents/i18n-hardcoded-cjk-report.md` for current debt.

---

## 1. File layout

```
frontend/src/locales/
├── index.ts                  bootstrap (i18next.init); DO NOT add keys here
├── en-US/
│   ├── index.ts              auto-generated aggregator (back-compat)
│   ├── common.ts             cross-cutting strings (buttons, statuses, login)
│   ├── navigation.ts         sidebar / menu labels
│   ├── business.ts           cross-cutting business glossary (agent, role, ...)
│   ├── agents.ts             pages/Agents.tsx + AgentDetail
│   ├── roles.ts              pages/roles/*
│   ├── actionspace.ts        pages/actionspace/* + RulesCard / EnvVarsCard
│   ├── actiontask.ts         pages/actiontask/* (incl. supervisor card)
│   ├── parallellab.ts        pages/actiontask/parallellab/*
│   ├── knowledgebase.ts      pages/knowledgebase/* (LightRAG, RAGAS, ...)
│   ├── memory.ts             pages/memory/*
│   ├── models.ts             model configuration + model list / form
│   ├── settings.ts           pages/settings/*
│   ├── mcp.ts                pages/settings/MCPServersPage.tsx
│   ├── im.ts                 pages/settings/IM Integration
│   ├── graph.ts              pages/settings/GraphEnhancementSettingsPage/*
│   ├── logs.ts               pages/settings/LogsPage
│   ├── about.ts              pages/settings/AboutPage
│   ├── oneclick.ts           components/OneClickGeneration/*
│   ├── users.ts              user management + role management
│   ├── account.ts            payments / profile / password change
│   ├── workspace.ts          workspace browser / editor
│   ├── history.ts            pages/History.tsx
│   └── home.ts               pages/Home.tsx
└── zh-CN/                    same shape as en-US/
```

- **One namespace per feature area.** Mirror the `pages/<feature>/` layout
  when in doubt.
- The aggregated default export (`zh-CN/index.ts`, `en-US/index.ts`) is the
  back-compat shim. Existing `useTranslation()` calls (no argument) still
  resolve against the **merged flat object** registered as the
  `translation` namespace.
- New code SHOULD prefer the scoped form:

  ```tsx
  const { t } = useTranslation('agents');
  t('agents.title');           // -> 'Agent Management'
  t('agents.col.name');        // -> 'Name'
  ```

- Cross-namespace keys (e.g. `common.cancel` from inside `agents`) work
  out of the box because `fallbackNS = 'translation'` is set in
  `locales/index.ts`.

## 2. Adding new translations — workflow

1. Decide which namespace the strings belong to (use the page's feature
   directory as the hint). If none fits, add a new namespace:
   - create `en-US/<ns>.ts` and `zh-CN/<ns>.ts` with the same template as
     existing files,
   - append the namespace name to `NAMESPACES` in
     `frontend/src/locales/index.ts`,
   - append the import + spread to `en-US/index.ts` and `zh-CN/index.ts`
     (mirror the existing block exactly).
2. Add the new key(s) to BOTH languages, side-by-side. Group them under a
   `// ----- <topic> -----` comment so future readers can navigate the file.
3. Use named placeholders for interpolation:

   ```ts
   'agents.deleteWarning': 'Are you sure you want to delete agent "{{name}}"?',
   ```

   Call as `t('agents.deleteWarning', { name: agent.name })`.
4. Run the key-consistency checker:

   ```bash
   cd frontend && node scripts/check-i18n-keys.js
   ```

   It exits non-zero if a key exists in one language only or per-namespace
   counts drift.
5. Commit. Optionally re-run

   ```bash
   node scripts/scan-hardcoded-cjk.js --md > ../docs/agents/i18n-hardcoded-cjk-report.md
   ```

   to refresh the debt report.

## 3. Hard rules (red lines)

- ❌ **No hard-coded user-visible CJK** in `.tsx` source. Anything the user
  can read on screen must go through `t()`.
- ❌ **No `t('foo') || '中文 fallback'`** patterns. The fallback ends up
  showing on English locales. Add the key for real.
- ❌ **Do not edit only one of `zh-CN/<ns>.ts` / `en-US/<ns>.ts`.** Both
  must move together; the checker enforces it.
- ❌ **Do not put new strings into a new monolithic `zh-CN.ts` / `en-US.ts`
  pair.** The old files have been deleted; do not recreate them.
- ✅ Code comments and `console.*` messages are excluded from this rule —
  they are not user-visible. Keep them in English.

## 4. What's still bad (debt)

`docs/agents/i18n-hardcoded-cjk-report.md` is auto-generated by
`frontend/scripts/scan-hardcoded-cjk.js` and lists every `.tsx` page sorted
by hard-coded-CJK line count. Each entry includes:

- `UV`: user-visible CJK lines (excluding comments / `console.*`).
- `JSX` / `Prop` / `Toast` / `Fallback` / `Other`: category breakdown so
  you can guess how big the migration is before opening the file.

Pick a file from the top of the list, open both
`zh-CN/<ns>.ts` and `en-US/<ns>.ts`, add the keys, rewrite the page to use
`t(…)`, then re-run the scanner. Each PR ideally clears one or two files
end-to-end rather than leaving half-done pages.

## 5. Migration cheat sheet

| Pattern (BAD)                                            | Pattern (GOOD) |
|---|---|
| `<Button>创建</Button>`                                   | `<Button>{t('agents.create')}</Button>` |
| `<Card title="历史记录">`                                 | `<Card title={t('history.title')}>` |
| `<Modal title="评测详情">`                                | `<Modal title={t('ragas.detail.title')}>` |
| `placeholder="选择知识库"`                                | `placeholder={t('ragas.selectKnowledgeBase')}` |
| `label="评测名称"`                                        | `label={t('ragas.col.name')}` |
| `message.error('删除失败')`                               | `message.error(t('agents.deleteFailed'))` |
| `t('foo.bar') \|\| '默认中文'`                            | Add real key; drop the OR. |
| `<Text>暂无知识库</Text>`                                 | `<Text>{t('knowledgeBase.empty')}</Text>` |
| Table column `title: '名称'`                              | `title: t('agents.col.name')` |
| Hardcoded fallback `\`使用 ${p.name} 登录\``              | `t([\`login.oauth.${id}\`, 'login.oauth.generic'], { name })` |
